Fixed in `arrowGeometry` (`preview/main.ts`): a non-box element's vertical-mode x-anchor is now its content rect's *left* edge, which is the same for every left-aligned line regardless of length. A real box (callout/study) still anchors on its own center, unaffected.
- [x] 19.2 Root cause of the overlap: two elements sitting side by side on the same text row (e.g. two `{#id}` spans sharing a line) were still routed through ordinary `wire` left/right-margin routing, meant for annotations that can be far apart vertically — for two things a few words apart, that's a huge unnecessary detour, and in a narrow pane the margin-side entry point can land past the visible edge, forcing the connector back across the very text it points at (exactly what the screenshot showed). Added a new `sameRow` geometry mode: when two elements' vertical centers nearly coincide, route a short direct arc between their facing edges instead of detouring to the page margin. Excluded from the side-based lane-packing pass (`assignLanes`), which doesn't apply to it.
- [x] 19.3 Verified via the Playwright harness at both narrow (460px, matching the reported screenshot) and wide (900px) widths: the flow chart's connectors are now a single straight vertical line down the whole chain, and the same-row arrow is now a small arc sitting just above the text, not crossing it. Re-checked `lecture-full.yamd`'s box-anchored (callout/study) arrows for regressions — none, since those still use center-anchoring, untouched by this fix.
- [x] 19.4 Added two requirements to this change's delta spec covering both fixes. Ran `npm run typecheck && npm test` (438/438, no core-level change — this was preview-only JS), rebuilt and reinstalled (`make install-fast`).

## 20. A same-line step's narrow `<span>` was failing the flow-chart "is this a box" check

A follow-up screenshot (same flow chart, narrow pane) showed `receive --> validate` still using the old left-margin elbow instead of task 19's new straight-column routing, even though `validate --> approved` and the rest of the chain were fixed.

- [x] 20.1 Root cause: `bothBoxy`'s width fallback checked `fromBox.width`/`toBox.width` directly — for "receive" (one of two `{#id}` steps sharing the "Start Receive request" line, so it's a narrow inline `<span>`, not a full-width `<p>`), that own width almost never clears the 30%-of-page threshold, so the pair fell through to ordinary `wire` routing instead of the top-to-bottom flow-chart routing task 19 added.
- [x] 20.2 First fix attempt (`blockWidth`: use the nearest non-inline ancestor's width for any inline element) over-corrected and broke a different, already-working case, caught before shipping by directly inspecting the rendered geometry (not just a screenshot): a prose word annotation like `[mitosis]{arrow=...}` mid-sentence is *also* a narrow `<span>` inside a wide paragraph, so it started being misclassified as a flow-chart step too, collapsing into a degenerate near-zero-length "vertical" connector instead of its correct `wire` routing.
- [x] 20.3 Replaced it with `stepWidth` + `isSegmentedLine`: a `<span>`'s containing paragraph's width is used only when that paragraph's other content is just whitespace and other id-bearing elements (i.e. the paragraph *is* a row of `{#id}` steps) — not when it contains real surrounding prose text. Verified via the harness: `mitosis`/`wire`/`curve` prose annotations are back to correct `wire` routing, `start --> receive` still uses the same-row arc, and `receive --> validate` now correctly uses top-to-bottom routing (with one jog at the transition point, since "receive" isn't at its line's start — expected).
- [x] 20.4 Noticed and deliberately did not touch: `parser.ts`, `lint.ts`, `render.test.ts` and `yamd-spec.md` all changed on disk mid-session from a concurrent, unrelated edit (a new `nestMarkerChanges` bullet-list-nesting feature), which left one pre-existing test (`Y212 changed bullet marker`) failing — confirmed unrelated by running the arrow/flow-chart test groups in isolation (all passing) rather than blocking on the full suite.
